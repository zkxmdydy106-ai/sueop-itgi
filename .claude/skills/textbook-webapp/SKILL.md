# 교과서 → 수업잇기 (전체 흐름)

이 스킬은 **순서와 관문**만 다룬다. 각 단계의 방법은 표시된 스킬을 그때 읽는다.
목표: 선생님이 내일 수업에서 링크 하나로 열어 바로 쓰는 것. 교과서 글은 그대로, 화면은 깔끔하게, 기록은 남게.

## 0. 처음 대화 (짧게)

**처음 쓰는 선생님(이 폴더를 GitHub에서 막 받았거나 `작업물/`이 비어 있음)** 이면 먼저 `§처음 쓰는 선생님` 을 따른다.

PDF가 `교과서_넣는곳/`에 있는지 먼저 본다 (없으면 대화에 끌어다 놓아 달라고 한 줄로 — 받은 PDF는 Code가 `교과서_넣는곳/`에 복사).
그다음 **예시 화면을 먼저 보여 주고**(`docs/예시화면/` 이미지 4~5장을 `SendUserFile`로 — 칠판 화면·원본 보기·3D 모형·학생 학습지·선생님 기록)
"이런 모양으로 만들 거예요"를 3줄로 말한 뒤, `AskUserQuestion` **한 번**에 묻는다 (이미 말한 것은 묻지 않는다):
- 어느 범위부터? 몇 쪽부터 몇 쪽까지 — 목차는 `extract.py`의 outline으로 보여 줄 수 있다. 나중에 쪽을 더 붙일 수 있다고 덧붙인다
- 원하는 방향 — 예시와 똑같이 / 바꾸고 싶은 점 말하기 (예: 테마 색, 3D 모형 많이·적게, 학습지 문항 수, 글자 크기)
- **태블릿 수업을 할까요?** — ① 학생 아이패드·휴대폰으로 학습지·즉석 질문·기록까지(서버·학생 링크·반) ② **수업 자료로만**: 전자칠판 화면·판서·학습지 인쇄만(반 편성·학생 로그인 없음).
  ②이면 `config.js`에 `noStudents: true` → 칠판에서 「반 선택」·학생 기능이 숨고 「학습지 만들기·인쇄」만 남는다. 서버는 칠판 링크용으로만 쓴다(학생 주소·명단 안내 생략).
- **반 운영** — 학년·반 번호로 들어오게 할지, 선택과목처럼 반 이름(예: 기하반)으로 할지. 반 이름이면 배포 뒤 선생님 기록 › 설정 「선택과목 반 이름」(또는 `join/{코드}.classIds`).
- **문제 화면 배치** — 과목마다 다르므로 꼭 묻는다. 예시: 수학은 「왼쪽 문제 · 오른쪽 그림/판서 칸」, 「크게 보기」에서 오른쪽 칠판에 풀이(그림을 칠판으로 가져와 표시 가능).
  탐구(과학·사회)는 「자료·그래프 크게 + 아래 발문」, 국어·영어는 「지문 왼쪽 · 문제 오른쪽」 등을 보기로 보여 주고 선생님 방식대로. 답을 BRIEF '결정 기록'에.
- **학습지 인쇄 양식** — "평소 쓰시는 학습지 파일(한글 .hwp/.hwpx, PDF, 워드)이 있으면 대화창에 넣어 주세요. 인쇄할 때 그 모양(제목·단원명 칸·테두리·글꼴·풀이 칸)으로 맞춰 드려요. 없으면 기본 양식으로 해요."
  받으면: 한글 파일은 한컴 COM(`HWPFrame.HwpObject` → `SaveAs(PDF)`)이나 `hwpx` 스킬로 PDF·그림으로 바꿔 **Read로 직접 보고**, 쪽 크기·여백·제목·표·글꼴·색을 재서
  `작업물/<이름>/print/worksheet.css`를 쓰고 `config.js`에 `printCss: 'print/worksheet.css'` (엔진은 `.wsp--custom` 틀: `.wspc-top`(큰 제목·<학습지>·학번 이름) · `.wspc-unit`(단원명 칸) · `.wspc-frame`(쪽마다 테두리) · `.wsp__sec`(묶음 제목) · `.wsp__item`(문제와 풀이 칸) · `.wsp__key`(정답)).
  **똑같이 맞추는 법 (눈대중 금지 — 파일 속 실제 값을 읽는다)**: 한글이면 `SaveAs(HWPX)`(또는 hwpx 스킬)로 바꿔 압축을 풀고
  `Contents/header.xml`의 글자 모양(charPr: 글꼴 `fontRef`→fontface 이름, 크기 `height`(1/100pt), 색 `textColor`, 굵게·밑줄),
  문단 모양(paraPr: 정렬, 줄 간격 `lineSpacing`, 왼쪽·첫 줄 들여쓰기, 문단 위·아래 간격), 테두리(borderFill: 선 종류·굵기·색 — 이중선 포함)와
  `Contents/section0.xml`의 용지(pagePr: A4, 여백 mm), 표(셀 너비·높이·병합·테두리), 머리말(쪽마다 반복되는 제목·단원명 칸)을 표로 적은 뒤 CSS에 **같은 숫자**로 옮긴다
  (pt는 그대로 pt, HWPUNIT 7200=1in=25.4mm). 글꼴은 같은 이름을 먼저 쓰고(함초롬바탕·맑은 고딕 등) 없을 때 비슷한 것을 뒤에.
  PDF로 뽑은 원본과 우리 인쇄 PDF를 **같은 배율 그림으로 나란히** 놓고 Read로 비교해 어긋난 곳(줄 간격·여백·글자 크기)을 고친다.
  예시 PDF를 뽑아 선생님께 보여 주고 고칠 점을 묻는다. **선생님 양식 파일·CSS는 작업물에만 두고 저장소에 올리지 않는다.**
- **학생 답 입력 기호** — 단원마다 필요한 기호를 정해 `content.js`의 `units[].keys`에 넣는다(예: 벡터 → | √ / ( ) , θ °). 과목 기본값은 `DT.keyDefaults`.
- 쓰는 곳 — 반 학생 기록까지(서버 자동으로 만들어 드림, 선생님은 구글 로그인만) / 우선 이 PC에서 체험

과목이 영어면 읽어 주기가 켜진다는 것만 알린다. 질문은 3개 이하. 답을 BRIEF '결정 기록'에 적는다.

## 1. 폴더와 장부

```
python tools/build/new_course.py "<과목>_<출판사>" --subject <수학|과학|국어|사회|영어|정보|기타> --course "<과목명>" --publisher "<출판사>"
```
`작업물/<이름>/BRIEF.md`를 채운다: 교과서 정보, 선생님이 고른 것. **요구사항 장부는 지우지 않는다** — QA가 이 표로 확인한다.
과목 색 이름이 없는 과목(보건·체육·음악·미술·기술가정·한문 등)은 `기타` 또는 가장 가까운 것. 화면 설계는 `subject-pedagogy`가 정한다.

## 2. 추출 → 눈으로 보기  (`textbook-ingest`)

```
python tools/ingest/extract.py "교과서_넣는곳/<파일>.pdf" --out "작업물/<이름>/content" [--pages 70-120]
```
- 암호·복사 금지면 도구가 멈춘다 → 우회하지 않는다. `copyright-guard`의 안내 문구로 선생님께 알린다.
- `_extract/report.md`를 읽고, 쪽 그림 2~3장을 **Read로 직접 열어** 쪽 번호 보정·재단이 맞는지 확인한다.

## 3. 첫 소단원 하나 만들기

순서대로 (소단원 하나 = 보통 교과서 4~8쪽 = 칠판 화면 8~16장):

1. **쪽을 읽는다** — 그 소단원의 쪽 그림을 전부 Read로 본다(`pages/hi/`). 글 줄은 `_extract/pages.json`에서 가져오되, 그림 속 글·수식·표는 그림을 보고 옮긴다.
2. **화면 나누기** — 교과서 흐름(생각 열기 → 개념 → 예제·문제 → 탐구 → 정리)을 그대로 따라 STEP을 붙인다. 한 화면 = 칠판에서 한 번에 설명할 분량. (`textbook-content` §화면 나누기)
3. **글 옮기기** — 요약 금지. 교과서 문장·수식·문제 번호·쪽수 그대로. 핵심어는 `[[ ]]` (빈칸 학습지·용어 뜻이 여기서 나온다).
4. **시각화 계획** — 소단원의 개념마다 "학생이 머릿속으로 그려야 하는 것"을 찾는다. 교과서 그림이 있으면 그 톤으로, 없으면 새로. 3D가 맞는지 viz가 맞는지는 `lab-3d` §고르기. BRIEF의 '시각화 계획' 표에 적는다.
   **탐구 그림은 소단원마다 최소 하나 — 자동으로 넣는다(선생님이 따로 부탁하지 않아도).** 학생이 조절 막대를 움직여 답을 찾는 모형(`lab` 블록 + `ask` 탐구 질문 한 줄). 칠판 「학생과 같이」를 누르면 학생 아이패드에 같은 모형이 열리고 고른 값이 막대그래프로 모인다. 입체·공간·회전이면 3D, 평면·그래프면 2D(SVG). 만드는 법·품질 기준은 `lab-3d` §9.
5. **평가 거리** — 문제마다 `grade`(채점 키), 탐구는 `act`(모둠이면 group), 성취기준 `standards`(실제 코드, 모르면 검색 — 지어내지 않는다), 진로 `explore` 2~4개, 더 풀어 보기 `practice`. 용어 `glossary`(뜻은 교과서 문장). 원본 쪽 `hotspots`(3D 버튼 자리).
6. **색인** — `python tools/ingest/attach_index.py 작업물/<이름>/content`

## 4. 검증 (소단원마다, 생략 금지)

```
python tools/verify/check_content.py 작업물/<이름>            # 형식·수식·그림·모형  ✗ 0
python tools/ingest/coverage.py 작업물/<이름>/content --pages 72-76   # 교과서 글 빠짐 0 (머리말·쪽 번호는 --ignore)
python tools/verify/audit_app.py 작업물/<이름> --shots        # 넘침·오류 0 + 스크린샷
python tools/verify/flows.py 작업물/<이름>                    # 버튼을 실제로 눌러 봄(학습지·묻기·모둠·학생 제출) + 서버 저장 규칙 → ✗0
```
- 스크린샷(`작업물/<이름>/.review/`)을 **Read로 연다.** 원본 쪽 그림과 나란히 놓고 본다.
- 병렬로: `content-auditor`(원본 대조), 첫 소단원이면 `first-time-teacher`, 소단원이 3개 이상 쌓이면 `pedagogy-reviewer`.
- 지적을 고치고 다시 검증. ✗를 남긴 채 다음으로 가지 않는다.

## 5. ⛔ 관문: 첫 소단원 확인 (반드시)

첫 소단원이 검증을 통과하면 멈추고 보여 준다:
- 칠판 화면 2~3장(개념·문제·탐구), 원본 보기(책 펼침), 3D 모형 1장, 학생 학습지 1장 — `SendUserFile`로 이미지 전송
- 직접 열어 볼 방법: `작업물/<이름>/app/index.html` (더블클릭 → 체험 모드) 또는 로컬 서버
- 이번에 정한 방식 3~4줄 (화면을 어떻게 나눴는지, 무엇을 3D로 했는지, 학습지에 무엇이 나가는지)

그리고 `AskUserQuestion`:
> **"첫 소단원을 이렇게 만들었어요. 이대로 나머지도 만들까요, 아니면 업그레이드할 점이 있을까요?"**
> - 이대로 진행 — 같은 방식으로 다음 소단원들을 만들어요
> - 업그레이드할 점 말하기 — 고칠 점을 알려 주시면 반영해서 다시 보여 드려요

- 답을 BRIEF.md '결정 기록'에 날짜와 함께 적는다.
- 업그레이드 → 반영 → 4번 → 다시 이 관문.
- **답을 받기 전에 다음 소단원을 만들지 않는다.** 선생님이 자리를 비웠으면 여기서 멈추고 기다린다(이 관문은 무인 작업 중에도 건너뛰지 않는다).
- 다른 과목·다른 유형(예: 수학 → 같은 책의 통계 실험 단원)이 처음 나오면 그 첫 소단원 뒤에 한 번 더 묻는다.

## 6. 나머지 소단원

확인된 방식 그대로 3~4번을 소단원마다 반복. 단원 하나가 끝날 때마다 BRIEF '상태'와 '한 줄'을 갱신(다음 세션이 이어서 할 수 있게).
큰 교과서는 한 번에 다 하지 않는다. 단원 단위로 끝내고 진행 상황을 알린다.

## 7. 배포 — 선생님은 로그인만  (`classroom-firebase`)

체험 모드로 충분하면 배포하지 않아도 된다(같은 기기 안에서만 기록). 반 학생이 쓰려면 Firebase — **서버 만들기·교과서 올리기는 Code가 한다.**
```
npx -y firebase-tools login --reauth                       ← 터미널 탭에서. 열린 구글 화면에서 선생님이 「허용」 (Code가 브라우저로 도와줘도 됨)
python tools/deploy/new_server.py "작업물/<이름>" --teacher 선생님@학교.kr   ← 프로젝트·Firestore(서울)·익명 로그인·웹 앱 설정
  (출력에 [브라우저 단계]가 있으면 Code가 콘솔에서 Google 로그인을 켠다 — 공개 이름 「수업잇기」, 지원 이메일 = 선생님)
python tools/deploy/deploy.py "작업물/<이름>"                 ← 엔진 반영·보안 규칙·호스팅·교과서 올리기·링크 출력 (링크.txt)
```
- 배포 직전 `privacy-guard` + `qa-tester`. 교과서 내용(content)은 공개 호스팅에 올리지 않는다 — Firestore(명단 학생·선생님만)와 칠판 링크용 사본(열쇠 링크)에만.
- 연결 활동(예: 드론 미션)이 있으면 `작업물/<이름>/extras/`에 파일을 두고 `app/config.js`의 `extras`에 주소를 적는다 → 칠판 수업 도구·학생 앱·선생님 설정에 버튼과 QR이 생긴다.

```

선생님 기록: https://….web.app/teacher.html — 학교 계정이 아닌 학생만 설정에서 「받기」
칠판에서 학생 기능(즉석 질문·학습지)을 쓰려면: 「반 선택」 → 휴대폰 QR로 열기 (한 학기 유지)

```
과정 요약은 하지 않는다.

## 9. 쪽을 더 만들 때 (같은 링크에 이어 붙이기)

- **같은 `작업물/<이름>` 폴더**에 소단원을 더한다(새 폴더·새 서버를 만들지 않는다). 쪽 그림이 없으면 `extract.py --pages`로 그 쪽만 더 뽑는다.
- **화면 번호(id)는 절대 바꾸지 않는다.** 학습지·제출·판서·기록이 화면 번호에 붙어 있다. 화면을 나눌 일이 생기면 `s17b`처럼 새 번호를 붙이고, 지울 때도 같은 번호를 다른 화면에 다시 쓰지 않는다.
- `deploy.py`를 다시 돌리면 바뀐 것만 올라가고, 링크(칠판 열쇠 포함)·반·명단·학생 기록은 그대로다. 기기에 저장된 교과서도 새 판만 다시 받는다.

## 처음 쓰는 선생님 (GitHub 링크 + PDF만 받은 경우)

1. **준비물 확인·설치는 Code가 한다**: `python --version`(없으면 https://python.org 안내), `node --version`(없으면 `winget install OpenJS.NodeJS.LTS` 제안),
   `pip install pymupdf pillow playwright && python -m playwright install chromium`. 실패한 것만 선생님께 한 줄로 알린다.
2. 이 저장소가 아직 PC에 없으면: `git clone <링크> "%USERPROFILE%\Desktop\수업잇기"` → 그 폴더를 작업 폴더로 연다(이후 이 CLAUDE.md를 따른다).
3. PDF를 `교과서_넣는곳/`에 복사 → §0(예시 화면 → 범위·방향 질문) → §1~6 → 첫 소단원 관문 → 나머지 → §7 배포 → §8 링크.
4. 선생님께 부탁하는 것은 **구글 로그인과 「허용」, 첫 소단원 확인** 두 가지뿐. 콘솔 클릭·명령어 입력을 선생님께 시키지 않는다.

## 공유 체크리스트 — 저장소 주인 선생님이 요청한 것 (새 교과서마다 그대로 지킨다)

다른 선생님 것을 만들 때도 이 목록을 **처음 질문 → 만들기 → 배포 → 전달**에서 하나씩 확인한다. 기능은 엔진에 이미 있으니 켜고 맞추고 시험하면 된다.

**사용량 아껴 쓰기 (선생님 요청)**: 선생님이 정한 쪽 범위만 만들고 멈춘다 — 처음엔 소단원 하나, 그 뒤로도 한 번에 소단원 1~2개. 범위가 끝나면 BRIEF.md '남은 일'에 다음 범위를 적고 「다음 범위는 새 대화에서 '이어서 ○~○쪽'」이라고 안내한다(긴 대화를 이어 가지 않게). 학습지도 범위·문항 수를 정해 만들고, 앱의 「학습지 보내기 › 직접 고르기」로 선생님이 직접 만들 수 있음을 알려 준다. 권장 모델: Claude Code Opus 5.5 / Codex 최상위 모델.

**처음에 묻기**: 쪽 범위 · 원하는 방향 · 태블릿 수업 여부(수업 자료만이면 `noStudents`) · 반 운영(학년·반 / 반 이름) · 문제 화면 배치(과목별) · 답 입력 기호(단원별 `units[].keys`) · 학습지 양식 파일(똑같이) · 연결 활동(드론처럼 직접 만든 것) · 학생 계정이 외부 앱에 로그인되는지.

**만들 때**: 교과서 글 그대로(요약·생략 금지) · 화면 넘침 0 · 원본 보기 · 시각화(교과서 그림 톤) · 학습지 거리(문제 채점키·탐구·진로·성취기준) · 변형 문제는 기본으로 넉넉히(개념당 10~12개, 정답은 코드 계산, 「변형」 표시 — 선생님이 골라 학습지에 넣음) · ⑴⑵ 소문항 키 · 답 모양(좌표 (x,y)·m=…,n=…·식)이 맞는 채점 키.

**엔진에 있는지 확인 (모두 켜져 있어야 함)**: 칠판 링크(로그인 없이)·짧은 주소+6자리 코드 · 칠판 QR 로그인 · 반 선택/없으면 안내 · 학생 링크 QR·클래스룸 · 학생 자동 명단(학교 계정 바로, 그 외 「받기」, 반 이름) · 학습지 보내기/직접 고르기(칠판·선생님 둘 다)·개념별 고르기·문장 어디나 빈칸·지문 가져오기(문장 골라 넣기)·내 문제 쓰기(보이는 그대로 칸·수식 버튼) · 학습지 기한 없음 · 문제 모음 PDF·인쇄(선생님 양식) · 학생에게 묻기(⑴⑵ 칸 나눔·그림 답·문항별 결과) · 문제에 맞는 답 칸·기호 자판·그리기 판 · 크게 보기 「그림 칠판으로」 · 판서 도구 줄 접기 · 필기·판서 다른 기기에서 이어 쓰기 · 화면 테마 7가지 · 선생님 화면 휴대폰 맞춤 · 아이폰 로그인(authHere + OAuth 리디렉션 URI) · 실패하면 빨간 알림(조용한 실패 없음).
