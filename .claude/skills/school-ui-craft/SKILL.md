# school-ui-craft — 학교 웹앱 화면 기준

이 프로젝트의 모든 화면은 **"전문 제품팀이 학교를 위해 만든 도구"**처럼 보여야 한다.
기준선은 frontend-design(방향·과정)과 이 문서(학교·한글 현장 기준)이고, 홈페이지형 페이지는 design-taste-frontend를 추가로 따른다.

## 1. 먼저 정할 것 — 화면의 직업

화면마다 아래 중 하나의 직업을 고르고 BRIEF.md에 적는다. 직업이 디자인을 결정한다.

| 직업 | 예 | 디자인 성격 |
|---|---|---|
| **업무 도구** | 출결 점검, 원서 현황 변환, 서식 작성 | 열자마자 일. 히어로 없음. 정보 밀도 높게, 장식 0. 키보드·붙여넣기·엑셀 친화 |
| **학생 활동** | 학습지, 퀴즈, 탐구 시뮬레이션 | 한 화면 한 과제. 큰 터치 영역. 진행 상황이 보임. 개념이 주인공 |
| **교실 화면** | 전자칠판 타이머, 발표 순서, 실시간 결과 | 5m 뒤에서 읽힘. 글자 매우 큼. 대비 강함. 조작은 교사만 |
| **안내·신청** | 가정통신, 행사 신청, 학교 소개 | 신뢰감·공문 톤. 읽기 편한 본문. 인쇄 고려 |
| **현황판** | 제출 현황, 점수 분포, 급식 | 숫자가 주인공. dataviz 원칙. 한눈 비교 |

## 2. 사용 환경 (모두 시험 대상)

자세한 수치는 `references/contexts.md`. 요약:
- 교사 PC: 1366~1920px, 크롬/엣지, 학교망(외부 CDN이 막힐 수 있음 → 글꼴 대체 글꼴 스택 필수)
- 학생 아이패드: 820~1180px, 사파리, 터치 44px 이상, 첫 터치 전 소리 불가
- 휴대폰: 360~390px, 가로 스크롤 0
- 전자칠판: 1920×1080, 3~6m 거리, 본문 최소 28px
- A4 인쇄: `@media print` 필수(배경·버튼 숨김, 쪽 나눔, 흑백 대비)

## 3. 한글 타이포그래피 — 품질의 70%

- 글꼴은 `references/fonts.md`에서 **앱마다 다르게** 고른다. 직전 앱과 같은 조합 금지(`design/journal.md` 확인).
- 시스템 기본(맑은 고딕·Apple SD 고딕)만 쓰고 끝내지 않는다. 단, 대체 스택은 반드시 둔다.
- `word-break: keep-all; overflow-wrap: anywhere;` — 한글 단어 중간 줄바꿈 방지.
- 본문 15~17px, 행간 1.6~1.75. 제목 행간 1.2~1.35, 자간 -0.01~-0.03em(크기가 클수록 더 좁게).
- 숫자 열은 `font-variant-numeric: tabular-nums;` — 점수·학번·시각이 세로로 맞아야 한다.
- 굵기 단계는 2~3개만(예: 400/600/800). 모든 제목을 700으로 두지 않는다.
- 한 줄 길이 한글 기준 35~45자. 넓은 화면에서도 본문을 끝까지 늘리지 않는다.
- 날짜·시간 표기는 한국식: `10월 16일 (금)`, `3교시`, `오후 2:30`. 학번 `2학년 3반 15번` 또는 `20315`.

## 4. AI 티 제거 — 전달 전 반드시 대조

`references/ai-tells-ko.md`의 목록을 화면 하나하나와 대조한다. 훅(`design_lint.py`)이 기계적으로 잡을 수 있는 것은 잡지만, 대부분은 눈으로 봐야 한다.
가장 흔한 다섯 가지:
1. 보라-파랑 그라데이션, 유리 효과(blur), 모든 카드에 같은 그림자
2. 제목마다 이모지(🎯✨🚀📊), "환영합니다! 👋", 느낌표 남발
3. 아이콘+제목+설명 카드 3개가 나란히 — 내용이 그 모양이 아닌데도
4. 모든 것을 가운데 정렬한 랜딩 페이지 구조를 업무 도구에 씌움
5. "스마트한", "손쉽게", "한눈에", "AI 기반" 같은 홍보 문구

## 5. 마감 기준 (전문가 수준의 차이)

`references/craft.md`에 항목별 기준. 핵심:
- **상태를 전부 디자인한다**: 비어 있음, 불러오는 중, 오류, 1개, 300개, 아주 긴 이름. 빈 화면은 "무엇을 하면 되는지"를 말한다.
- **간격은 하나의 리듬**(4px 배수)으로. 임의 값(13px, 27px) 금지.
- **색은 역할로 정의**: `--ink`, `--ink-soft`, `--surface`, `--line`, `--accent`, `--danger`… 화면 코드에 hex를 흩뿌리지 않는다.
- **강조는 한 곳에만**. 화면마다 시선이 처음 갈 곳 하나를 정하고 나머지는 조용히.
- **포커스 링·키보드 조작·`prefers-reduced-motion`·대비 4.5:1** — 말하지 않고 기본으로.
- **인쇄**: 교사는 결국 출력한다. 인쇄 미리보기에서 A4 한 장에 깔끔히 떨어지는지.

## 6. 문구 (UX writing)

- 존댓말 "~해요"(학생용) 또는 "~합니다"(교사·가정용) 중 하나로 앱 전체 통일.
- 버튼은 동사로 결과를 말한다: "제출" → "답안 제출하기", "확인" → "명단 불러오기". 같은 행동은 끝까지 같은 이름.
- 오류는 사과하지 않고 원인과 해결을 말한다: "학번은 5자리 숫자예요 (예: 20315)".
- 학생용 문구는 생활어. 전문 용어는 개념 학습 대상일 때만.
- 학교 현장 단어를 쓴다: 교시, 학번, 담임, 나이스, 생기부, 수행평가, 결재, 가정통신문.
- 문구 검토는 `ux-writer` 에이전트에 맡길 수 있다.
