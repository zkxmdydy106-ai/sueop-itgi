# school-webapp — 동작 기준과 검증

(기존 `project/skills/webapp`에서 이식. 검증기 코드 동일.)

## 0. 제1원칙 — 내 환경에서 열린다 ≠ 쓸 환경에서 된다

같은 HTML이 **Apps Script iframe, claude.ai 미리보기, 아이패드 사파리, 휴대폰**에서 각각 다르게 동작한다.
"됐다"는 판정은 사용자가 실제로 쓰는 환경 기준으로만 한다. 그 환경을 직접 못 열었으면 못 열었다고 밝힌다.

## 1. 요구사항 장부 — 가장 먼저 만들고 끝까지 유지

앱 폴더의 `BRIEF.md` "요구사항 장부"에 **한 줄씩** 적는다. 형식: `누가 · 어디서 · 무엇을 하면 · 무엇이 되어야`.

```text
- 학생 · 아이패드 · 학습지의 '3D 드론 미션 열기'를 누르면 · 시작 카드 없이 바로 게임 화면
- 참관 교사 · 휴대폰 · 인쇄본 QR을 찍으면 · 게임이 '참관 선생님' 상태로 열림
- 담임 · PC · 나이스 엑셀을 끌어다 놓으면 · 서류가 빠진 학생만 빨간 줄로
```

- 작업 중 추가·변경된 요구도 **즉시** 장부에 넣고, 바뀐 요구는 옛 줄을 지운다.
- 전달 전 한 줄씩 대조한다(`qa-tester` 에이전트가 함께 대조). 대조 안 한 줄이 있으면 전달하지 않는다.
- 사용자가 화면을 직접 확인해야 하는 줄은 "수업 전 점검"으로 넘긴다.

## 2. 실행 환경별 함정 (코드 = 검증기가 자동 검출)

### Apps Script (HtmlService)

| 함정 | 해야 할 것 | 코드 |
|---|---|---|
| iframe 안이라 `location.search`로 `?m=…`을 못 읽음 | `google.script.url.getLocation(cb)`로 읽고 받은 뒤 화면 시작 | G2 |
| `google.script.run.X()`인데 `.gs`에 `function X` 없음 / 이름이 `_`로 끝남 | 서버 함수 이름 대조, 공개 함수는 `_` 없이 | G1 |
| `createHtmlOutputFromFile('drone')`인데 `drone.html` 없음 | 파일 이름 = 확장자 뺀 HTML 이름 | G3 |
| 서버 응답 뒤 `window.open` → 아이패드가 팝업 차단 | 주소를 미리 받아 `<a href>`에 | G4 |
| 상대 링크가 iframe 안에서만 바뀜 | `target="_top"` 또는 `"_blank"` | G5 |
| 배포 주소를 코드에 적어 둠 | `ScriptApp.getService().getUrl()`로 실행 시 받기 | — |
| 파일만 고치고 반영 안 됨 | **배포 → 배포 관리 → 새 버전**. 안내에 적는다 | — |
| 실시간 영상처럼 보내려 함 | 동시 실행 약 30개, 요청당 0.5~1초. 4초 주기 등으로 설계. CacheService 값 100KB 이하 | — |
| 교사용 화면이 학생에게 보임 | 서버에서 `isTeacher_()` 확인 | — |
| `setXFrameOptionsMode` 누락으로 다른 사이트에 못 넣음 | 임베드가 필요할 때만 `ALLOWALL` | — |
| 디자인이 GAS 기본 여백에 눌림 | `HtmlService…addMetaTag('viewport','width=device-width, initial-scale=1')` | H7 |

### claude.ai 미리보기 (Artifact)

| 함정 | 해야 할 것 | 코드 |
|---|---|---|
| 링크의 `?` 뒤가 지워짐 | 미리보기용 링크는 `#해시`, 받는 쪽도 해시를 읽음 | P1 |
| 미리보기 QR → Claude 앱이 열림 | 미리보기에서는 "배포 후 생성" 안내 | P2 |
| `[hidden]` 규칙이 미리보기 뼈대에만 있음 | 페이지 CSS에 `[hidden]{display:none!important}` | H4 |
| `window.print`·`alert`·`confirm` 동작 안 함 | 인쇄는 실제 배포 화면에서, 확인 창은 페이지 안에 | — |

### 아이패드 · 휴대폰

| 함정 | 해야 할 것 | 코드 |
|---|---|---|
| 390px에서 가로로 밀림 | 한 열로 쌓기, 고정 폭 금지 | R2 |
| viewport 메타 없음 | `width=device-width, initial-scale=1` | H7 |
| 터치 버튼이 작음 | 최소 44px | — |
| 입력 시 화면 확대 | 입력칸 글자 16px 이상 | — |
| 3D(WebGL)가 버벅임 | 픽셀비 상한 ≤2, 인스턴싱, 그림자 광원 1개, 느리면 품질 자동 하향 → "실제 기기 미시험" 밝힘 | — |
| 소리가 안 남 | 첫 터치 뒤 오디오 시작 | — |

### Netlify · GitHub Pages · 단일 HTML

- 정적 호스팅에 학생 개인정보(명단·성적)를 파일로 올리지 않는다. 명단은 사용자가 그때그때 불러오게.
- 단일 HTML 배포면 CSS·JS를 한 파일에. 외부 라이브러리는 버전 고정 URL(`@1.2.3`)만. (H6)
- `http://` 자원 금지 (H5).

## 3. 학교 수업 웹앱 기본 설계

- **이름은 한 번만**: 학습지에서 적은 학번·이름을 다른 화면으로 넘긴다 (주소값 + 기기 저장소).
- **화면은 바로 연다**: 이름이 없어도 첫 화면을 막지 않는다. 결과를 보낼 때만 묻는다.
- **역할 분리**: 학생 / 참관 교사 / 담당 교사. 참관 교사 기록은 통계에서 빼고, 입장 화면에 '참관 선생님' 선택.
- **교사 출발점 하나**: 모든 화면으로 가는 모음 화면.
- **기존 프로젝트 상속**: 같은 GAS 프로젝트면 기존 `Code.gs`의 저장·채점 규칙, 파일 이름 규칙, 디자인을 따른다.
- **저장소**: `localStorage`는 try/catch로 감싸고, 없어도 화면이 동작해야 한다.

## 4. 검증 (필수)

```bash
python .claude/skills/school-webapp/lib/verify_webapp.py 작업물/<앱폴더> --render
```

- HTML 태그 짝(H1), id 중복(H2), 스크립트가 찾는 id(H3), hidden 덮어쓰기(H4), http 자원(H5), 라이브러리 버전(H6), viewport(H7), 스크립트 문법(J1, node 있을 때), Apps Script 연결(G1~G5), 미리보기 함정(P1·P2), `--render` 시 휴대폰·아이패드 너비 실제 렌더(R1 스크립트 오류, R2 가로 넘침).
- **✗가 하나라도 있으면 전달하지 않는다.** △는 장부와 대조해 확인.
- 훅이 자동으로 돌린다: 파일 저장 직후(`post`) + 답변 끝내기 직전(`stop`, `--render` 포함).
- 검증기를 고치면 `python .claude/skills/school-webapp/lib/selftest_webapp.py`로 오탐 0·미탐 0 확인.
- 검증기로 알 수 없는 것: 장부 대조, 실제 배포 동작, 동시 접속, 실제 기기 속도 → 전달 때 밝힌다.

## 5. 전달

- 미리보기와 실제 배포의 차이를 한 줄로 (예: "미리보기에서는 기록이 저장되지 않고 QR이 만들어지지 않습니다").
- 수업 전 점검 3~5개 (실제 기기로 열기, QR 찍어 보기, 몇 명 동시 접속).
- 직접 못 해 본 것은 못 해 봤다고 쓴다.
